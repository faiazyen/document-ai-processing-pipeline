# Invoice Schema And Validation

## Target Invoice Schema

```json
{
  "document_type": "invoice",
  "supplier_name": "",
  "supplier_country": "",
  "buyer_name": "",
  "invoice_number": "",
  "invoice_date": "",
  "due_date": "",
  "currency": "",
  "subtotal": null,
  "vat_amount": null,
  "total_amount": null,
  "line_items": [
    {
      "description": "",
      "quantity": null,
      "unit_price": null,
      "total": null
    }
  ],
  "payment_terms": "",
  "confidence_score": 0,
  "validation_warnings": []
}
```

## Field Notes

- `document_type` should be `invoice` for valid invoice documents.
- Monetary values should be numeric where possible.
- Dates should be normalized consistently.
- `confidence_score` should be a number from `0` to `1`.
- `validation_warnings` should be generated by deterministic validation, not only by the AI response.

## Validation Rules

The system should flag:

- Missing invoice number.
- Missing supplier name.
- Missing buyer name.
- Missing invoice date.
- Missing total amount.
- Total lower than subtotal.
- VAT exists but total does not match subtotal plus VAT.
- Unknown currency.
- Empty line items.
- Low confidence extraction.

## Reliability Principle

This project should prioritize document reliability, not extraction glitter. A partially complete invoice with clear warnings is better than a confident-looking JSON object that hides uncertainty.

## Suggested Warning Format

```json
{
  "code": "missing_invoice_number",
  "severity": "high",
  "message": "Invoice number is missing."
}
```

Suggested severities:

- `low`
- `medium`
- `high`

## Suggested Validation Strategy

1. Validate required fields.
2. Validate numeric relationships.
3. Validate currency recognition.
4. Validate line item presence.
5. Validate confidence score.
6. Return warnings alongside the extracted invoice.
